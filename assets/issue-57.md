# Issue #57: Ignoring I/O cost of unnecessary outputs?

## Original post
- author: papp-pal-andras
- created_at: 2026-03-24T12:19:11Z
- url: https://github.com/yarongmu-google/MLSys/issues/57

<comment>
Hi! I would have an interpretation question for the cost function in the task.

Assume we have an example graph with the following edges:
Tensor0 -> Op0
Op0 -> Tensor1
Op0 -> Tensor2
Tensor1 -> Op1
Op1 -> Tensor3
Tensor2 -> Op2
Op2 -> Tensor4

Assume we form the subgraphs [0, 1] and [0, 2].

This means that Tensor2 is still an output in Subgraph0, although it is not required in any other subgraph due to the replication of Op0. Similarly, Tensor1 is an output in Subgraph1, but not required as an input anywhere.

In the cost calculation of Subgrpah0, is it valid to ignore the output cost of Tensor2 (i.e. implicitly assume this output is just discarded; this should be entirely possible in practice)? Or are we forced to account for the output cost of Tensor2 (for model simplicity) even when outputting it is not necessary?

Thanks a lot in advance!
</comment>

<comment>
Thanks for the questions.

@papp-pal-andras: You are correct that in practice it is possible; however, in this simplified world, this is not valid. Current spec says: "Any tensor not in this list is automatically evicted to the slow memory (if it is an output)." This charges eviction for ALL non-retained outputs, even unused ones. To avoid the cost of copying the throw away tensors, you will need to retain it.

@Richard1688Sun: The hardware doesn't know the "future"; ie whenever it finishes process a subgraph, it drops its outputs inside the fast memory, and will move them back to the slow memory, assuming they are useful. To prevent this from happening, you need to retain the tensor. 
</comment>
